# prek 導入設計

## 目的

このリポジトリで開発する全員が同じ Git hook 設定を共有し、コミット前チェックの入口を統一する。

## 方針

- Git hook の管理には `prek` を使う
- 設定ファイルはリポジトリのルートに置いて共有する
- 初回セットアップは `Makefile` 経由で実行させる
- `prek install` を `make setup` の一部に含める

## 採用理由

`Makefile` は導入コストが低く、初回セットアップ手順を 1 コマンドに集約しやすい。今後 Rust やフロントエンドのセットアップ項目を追加するときも同じ導線を拡張できる。

## 今回の実装範囲

- ルートに `prek` の設定ファイルを追加する
- ルートに `Makefile` を追加し、`make setup` から `prek install` を実行できるようにする
- ルートの `README.md` に初回セットアップ手順を追記する

## 今回やらないこと

- CI での強制
- 実際の hook 内容の拡充
- `nix` や devcontainer の導入

## 想定運用

開発者はリポジトリを clone したあと、最初に `make setup` を実行する。これにより `prek install` が走り、このリポジトリで共有される hook 設定がローカル Git に適用される。
